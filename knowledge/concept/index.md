# Concept
* [Addon aggregation: routing, manifest hints, timeouts, series and subtitles](addon-aggregation.md) - How core queries addons: routing by resource, type and idPrefixes, manifest behaviour hints and needs-configuration, streams embedded in meta, the addon User-Agent, timeouts and partial results, series and bingeGroup, and subtitle aggregation and conversion.
* [Delivery modes: direct, remux, transcode](delivery-modes.md) - How media reaches players: direct play, remux and transcode; core picks the cheapest that works from client capabilities and the engine probe; watch parties always transcode.
* [Engine descriptor and capabilities in core](engine-descriptor.md) - How core describes an engine: transport, address, capability flags (hwaccel, live and prepared heights, tonemap, sessionOverrides, concurrency, defaultBitrate), set via the admin API and gated at runtime.
* [Core media tokens: JWT path segments with epoch revocation](media-tokens.md) - HS256 JWT media tokens in the media URL path, default 8h lifetime, per-subject and per-session revocation, the 409 rule for denylisted subjects, and the secret-rotation behaviour.
* [Ranking settings: scores are settings, stored overrides, presets and language order](ranking-settings.md) - Every ranking number is an operator setting (tiers, hdr, decodeCost, container, size, language, resolution, release, binge, lastSource, debrid, safety), stored as overrides in core's settings table, changed through /v1/admin/ranking, shareable as presets, with the preferred-language resolution order.
* [Source list, ranking and playability rules](source-ranking.md) - How core annotates each addon candidate for the target engine: the standard source list, explain breakdowns, the playability rules and the numbered scoring rules (tiers, HDR, decode cost, container, size, mismatches, resolution).
